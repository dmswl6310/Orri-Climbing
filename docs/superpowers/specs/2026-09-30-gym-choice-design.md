# 암장 선택 검색과 비교

사용자가 방문 조건에 맞는 암장을 찾고 2~3개 후보를 비교해 선택하게 한다.
기존 목업 기반 서비스와 Next.js 서버 페이지 구조를 유지하며 사용자 요청대로 dev에 기능별 커밋 후 push한다.

## 검색
가격 상한(일일 이용권), 주차, 샤워실, 암벽화 대여, 초보자 체험 강습 필터를 AND 조건으로 적용한다.
미등록 가격/강습은 해당 조건에 일치하지 않는다. 가격 0원은 유효하다.
필터는 적용 버튼으로 URL에 반영하고, 정렬/키워드/GPS 변경에서도 유지한다.
필터 초기화는 키워드와 유효 위치를 보존하며, 전체 초기화는 /search로 이동한다.
0건은 0건으로 표시하고 추천 목록은 조건 밖 추천임을 명시한다.
중복/잘못된 파라미터는 안전하게 정규화하며 화면 상태와 서버 조건이 일치해야 한다.

## 비교
검색 카드와 상세에서 최대 3개를 선택한다. 선택은 페이지 이동/새로고침에도 같은 탭에서 유지한다.
브라우저 저장소가 차단되어도 현재 페이지 사용이 실패하면 안 된다.
고정 하단 비교 바는 이름, 개별 해제, 전체 해제와 비교 링크를 제공한다.
공유 주소 /compare?ids=... 를 서버에서 검증하고 ID 순서를 보존한다.
가격, 직선거리, 운영 시간, 주차/샤워실/대여, 초보자 강습, 난이도를 비교한다.
미확인은 불가와 구별하고, 모바일 표 영역만 가로 스크롤하며 키보드로 접근할 수 있어야 한다.
거리 계산을 위한 좌표는 비교 링크에 필요할 때만 포함하고 공유 안내에 알린다.
빈 목록/1개/잘못된 ID/중복/4개 이상을 명시적으로 처리한다.

## 완성도 다섯 가지
1. 자동완성/필터/비교 선택의 레이블, 포커스, 키보드, 상태 안내.
2. pending, 0건, 실패, 재시도, GPS 거부/경합 및 주소 API 실패 처리.
3. 가격/필터/좌표/비교 ID 입력 검증을 서버·클라이언트 공통 규칙으로 처리.
4. 이미지 오류와 잘못된 이미지 주소의 대체 화면, 비교에서도 같은 컴포넌트 사용.
5. 필터 정규화·URL 생성·암장 속성 판정·비교 선택을 역할별로 분리하고 기존 GPS/검색 재사용.

## 데이터
실제 가격/강습 정보를 추정하지 않는다. 사용자 데이터 선택을 기다리는 동안 동작 검증에는 테스트 fixture를 사용한다.
데모 추가 시 실제 암장과 혼동되지 않는 가상 이름과 데모 표기를 사용한다.

## 검증과 비범위
Vitest로 순수 검색 규칙, 가격 경계, 미확인 상태, 선택 제한/저장소 실패를 검증한다.
Testing Library로 URL 유지, 폼·선택 조작, 오류 처리를 검증한다.
Playwright로 데스크톱/모바일 검색·필터·비교·새로고침·공유·뒤로 가기 흐름과 너비를 검증한다.
DB·로그인·사용자 저장·실제 데이터 수집은 이번 요청에 포함하지 않는다.
